## Setup and reproduction

Use Python 3.10 or later. From the repository root:

```sh
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
make all
```

Re-run `pip install -e ".[dev]"` after pulling a change to `pyproject.toml`: Table 4's Ibbotson
block reads the Goyal-Welch `.xls` through `xlrd`, and without it the check prints a warning and
leaves those 24 cells unscored. `git lfs pull` fetches the factor files under `data/raw/french`
and `data/raw/goyal_welch`; without them the factor-regression rows are not computed either.

The replication pipeline is implemented and remains a **partial replication**.
The default `--specification baseline` reconciles PRs #8–10 and Eiko’s replacement
PR #12: a volume-based universe, July 1963 first cohort, separately compounded
books, stock-value short weights, and next-day execution in the signal direction.
RMS triggers, same-issuer exclusion, flat-path exclusion and the 95% stale screen
are disclosed conventions; alternatives remain available. Idle months earn zero,
but never-opened portfolios have undefined employed capital.

`--specification paper --start 1963-02 --report-start 1963-07` preserves the earlier
strict-price/warmup experiment; the historical name does not establish it as the
unique paper specification. `legacy` preserves the earlier accounting comparison.
Use separate `--cache-root` and `--out-root` paths for each specification.
See [the reconciliation](report/replication/PR_RECONCILIATION.md) for decisions,
old/new/paper comparisons, validation and reproduction commands. The extension
script remains a placeholder; `make all` rebuilds the replication only.

`make validate-fidelity` rebuilds five controlled variants and compares all of them
with the paper. It verifies the full reporting calendar, accounting identities,
and unchanged selections/trades where a rule should not affect them. See
[the fidelity validation](report/replication/FIDELITY_VALIDATION.md) for current
results, including deteriorations and inputs still unavailable. Use
`REPLICATION_WORKERS=1` on a machine with limited memory or free disk space.

### WRDS access

Data are pulled with the official `wrds` Python package. Each teammate stores
their own credentials once, outside the repository:

```sh
.venv/bin/python scripts/wrds_setup.py   # run in your own terminal; approve the Duo push
```

The script prompts for the password without echoing it and writes it to
`~/.pgpass` (mode 600). Code connects with `project.data.wrds_connection()`,
which reads that file and never takes a password argument. Each new connection
can trigger a Duo push, so reuse one connection per session. API pulls land in
the git-ignored `data/raw/wrds_api/`. Run `pre-commit install` once to block
commits that contain secrets.

The script order is:

1. `scripts/01_get_data.py` — acquire source data.
2. `scripts/02_build_dataset.py` — clean and merge the analysis dataset.
3. `scripts/03_replicate.py` — reproduce the original-paper experiment.
4. `scripts/04_extend.py` — run the extension experiments.

All research logic belongs in the importable `src/project/` package. Notebooks
are for exploration; reported results must be generated by the pipeline.
The `tests/` directory includes cash-flow, timing, data-integrity, and historical
rebuild checks. A good match to published numbers is evidence, not a test target
used to tune the strategy. Generated output stays in ignored `results/`.

## Replication status

The paper reports positive pairs-trading returns, weaker returns after 1988,
and robustness to several risk controls. Our results reproduce some patterns,
while numerical levels, tails, capital accounting and several robustness claims
remain unresolved. A weighted comparison score is not a fraction of proven claims.
Current results and the historical experiments are separated in these records:

- [Replication summary](report/replication/REPLICATION_SUMMARY.md): measured results and gaps.
- [Reconciliation](report/replication/PR_RECONCILIATION.md): Hao’s and Eiko’s additions, decisions and commands.
- [Claims ledger](report/replication/CLAIMS.md): each numbered claim with its evidence scope.
- [Historical main outputs](report/replication/outputs/): already-committed artifacts from `bc528c0`, not the reconciled baseline.
- [Score history](report/replication/SCORE_LOG.md): the archived 481-cell scoring series.
- [WRDS follow-up](report/replication/WRDS_FOLLOWUP.md): universe and CIZ/SIZ sensitivities, licensed input provenance, and unresolved factor inputs.

All new generated output goes under ignored `results/`. Restricted observations
stay local; queries and acquisition metadata may be committed.

and source attribution still apply. Intermediate/processed CRSP and TAQ data
remain ignored.

Generated results are ignored, apart from directory placeholders, and should be
rebuildable once the pipeline is implemented. Never commit credentials.

## Existing WRDS web exports

The importer preserves the original source and writes a SHA-256 audit manifest.
It rejects conflicting security-day records; exact duplicate analysis rows are
collapsed. CIZ `dlyret` already contains delisting returns.

```sh
python scripts/import_wrds_ui.py --daily-csv /path/to/daily_stocks.csv.gz --index-csv /path/to/daily_indexes.csv.gz
python scripts/03_replicate.py --specification paper
```

Do not mix old cohort caches with the corrected baseline: cache format 6 and all
method settings are checked. Use a new `--cache-root` or explicitly rebuild with
`--force`. Claim experiments reject incompatible input and output caches too.
